## 1. 输入需求

在 Trae IDE 的对话框中，直接用自然语言描述你的需求。

**方式一：纯文字输入**

```
我要做一个合同审批管理功能，给销售、销售主管、法务、财务和管理员使用。
销售创建合同后提交审批，主管审批通过后到法务，法务审批通过后合同生效。
金额超过 50 万元的合同需要增加财务审批节点。
驳回后合同终止，销售可以复制为新合同重新提交。
退回后销售可以修改后重新提交。
```

**方式二：文字 + 原始资料**

在对话框中拖入或粘贴参考资料，然后输入需求描述。

技能会自动识别：审批语义 → 启用审批流；多角色 → 权限差异；金额阈值 → 条件分支。

## 2. 自动初始化

技能会**自动**完成项目目录初始化（无需你操作）：
1. 推断目录名 → `contract-approval`
2. 创建 `contract-approval/`、`output/`、`raw-materials/`
3. 写入 `input.md` 和空 `project-state.json`
4. 如果有参考资料，保存到 `raw-materials/`

## 3. 原始资料处理

如果你提供了参考资料，技能会逐份读取并提取关键业务信息：

```markdown
当前节点：原始资料处理
已读取 3 份原始资料：

1. 聊天记录截图（chat-screenshot.png）
   - 提取到：合同审批流程为「销售提交 → 主管审批 → 法务审批 → 财务审批」
   - 提取到：金额超过 50 万元需要财务审批

2. 合同管理制度（contract-policy.docx）
   - 提取到：合同分为「标准合同」和「框架协议」两类

3. 客户名单（customer-list.xlsx）
   - 提取到：共有 156 个客户，分为 A/B/C 三个等级

请确认以上信息是否准确，并回答待澄清问题。
```

**你的操作**：确认准确 → 回复「确认」；有修正 → 直接指出。

## 6. 生成业务原型

确认功能清单后，技能生成高保真 HTML 原型。

**原型特点**：
- 纯 HTML + CSS，直接双击打开
- 完整的页面导航和状态切换
- 不同角色看到不同的操作按钮和数据范围
- 关键元素携带 `data-page-id`、`data-module-id` 等稳定属性

**你的操作**：在浏览器中打开 `index.html` 查看，确认后继续。

## 核心概念

### ProjectState
`project-state.json` 是单一事实源。所有产物从此渲染，修改需求时先更新 ProjectState 再重新渲染。

### 状态机
每个需求自动生成状态机（初始态 → 中间态 → 终态），包含触发动作、角色和非法流转拦截。

### 审批流
检测到审批语义关键词时自动启用，补齐审批节点、驳回规则、撤回规则、转审规则。

### 实体追溯
原型元素携带 `data-*` 属性 → PRD 章节引用 → 标注编号 → 测试用例覆盖，全链路可追溯。

### 增量修改
修改上游产物时，下游自动标记 dirty 并提供重新生成选项。

## 多角色审查系统

6 个 AI 专家角色在 5 个审查关口提供结构化反馈：

| 角色 | 职责 |
|------|------|
| 业务分析师 | 流程闭环、角色覆盖、审批逻辑 |
| UX 设计师 | 信息架构、页面结构、操作路径 |
| UI 设计师 | 组件选型、视觉层级、设计一致性 |
| 技术架构师 | 状态机完备性、权限模型、扩展性 |
| 前端开发 | HTML 语义化、无障碍性、组件质量 |
| QA 工程师 | 测试覆盖、边界值、异常流 |

**推荐策略**：L 级需求开启全部 5 个关口；M 级仅开 Gate 1 + Gate 5；S 级通常不需要。

启用方式：
- 对话中：「使用审查模式生成」
- CLI：`pnpm dev -- generate --input <路径> --review`
- 严格模式：`--review --strict`（critical 发现阻断生成）

## 入口模式

| 模式 | 触发关键词 | 走什么流程 |
|------|-----------|-----------|
| 新建 | 首次需求输入 | 完整闭环 |
| 变更 | 修改、调整、去掉 | 读取已有项目 → 变更 diff → 重新生成 |
| 配置变更 | 新增选项、修改阈值 | 配置清单 + 回归测试点 |
| Bug 修复 | XX不对、XX报错 | Bug 需求卡 + 回归测试 |
| 数据迁移 | 迁移、导入、历史数据 | 字段映射 + 清洗 + 验证 + 回滚 |
| 系统对接 | 对接、同步、推送 | 接口方案 + 异常处理 |
| 需求接入 | 我已有 PRD | 导入 → 前置检查 → 执行 |
| 恢复 | 继续上次的项目 | 读取断点 → 继续 |
