# B 端产品规则

用途：把旧版 PDT 的 B 端业务原型经验迁入 `ProjectState` 语义层。

## 页面建模

每个核心页面至少要能表达：

- 页面名称和页面目标
- 核心业务对象
- 当前业务状态
- 主操作区
- 关键模块边界
- 角色与权限差异
- 空状态、错误状态、无权限状态和加载状态

在 `ProjectState` 中优先落到 `page`、`module`、`field`、`action`、`permission`、`ui_state` 这些实体。

## 状态机

状态机默认必做。至少包含：

- 初始态、中间态、终态
- 触发动作
- 允许角色
- 进入条件和退出条件
- 非法流转拦截
- 状态历史或时间线

在 `ProjectState` 中优先落到 `business_state`、`state_transition`、`action` 和 `flow`。

## 审批流

只有出现审批语义时才启用审批流。触发词包括：

- 审批、审核、复核、提交审批
- 通过、驳回、撤回、转审
- 审批记录、审批节点、审批意见

启用后必须补齐：

- 审批节点
- 审批角色
- 节点动作
- 驳回原因
- 撤回规则
- 审批记录
- 不同角色按钮差异

## 原型挂载点

业务原型应优先使用稳定 data 属性支撑追溯：

```html
<section data-page-id="page_contract_detail" data-module-id="module_approval_actions">
  <button data-action-id="action_approve">通过</button>
</section>
```

标注、PRD、测试用例和一致性检查都应优先基于这些稳定 ID，而不是依赖页面文案猜测。

## 输入来源

需求输入支持以下来源，可单独使用或组合使用：

1. **对话文本**：用户在 Trae IDE 对话框中直接输入的需求描述。
2. **原始资料文件**：用户提供的参考资料，保存在 `<project-name>/raw-materials/` 目录中。支持的文件类型：
   - 图片（`.png`/`.jpg`/`.jpeg`/`.gif`/`.webp`）：聊天记录截图、流程图、白板照片等，由 AI 视觉能力识别。
   - Word 文档（`.docx`/`.doc`）：需求文档、管理制度、会议纪要等。
   - Excel 表格（`.xlsx`/`.xls`）：数据字典、配置清单、枚举值表等。
   - PDF 文档：合同模板、制度文件、行业规范等。
   - Markdown / 纯文本（`.md`/`.txt`）：结构化需求、技术方案等。
3. **对话中粘贴的附件**：用户在对话中直接粘贴的截图或拖入的文件，同样视为原始资料。

当存在原始资料时，必须先完成资料处理（提取信息、整理摘要、用户确认），再进入功能清单。原始资料中的信息优先级低于用户在对话中明确确认的内容。

## 主数据管理

当需求涉及客户、供应商、产品、组织架构、员工、仓库、银行账户等基础实体时，必须主动识别并建模主数据。

### 主数据识别规则

出现以下关键词时触发主数据建模：

- 客户、供应商、合作伙伴、经销商
- 产品、商品、物料、SKU
- 组织架构、部门、岗位
- 员工、人员、账号
- 仓库、库位
- 银行账户、收款账户
- 地址、省市区

### 主数据建模模板

每个主数据实体必须明确以下维度：

| 维度 | 说明 | 示例 |
|------|------|------|
| 数据来源 | 手动录入 / Excel 导入 / 外部系统同步 | 供应商手动录入，员工从 HR 系统同步 |
| 维护角色 | 谁创建、谁修改、谁停用 | 管理员创建，采购部修改，管理员停用 |
| 引用关系 | 哪些业务单据引用了该主数据 | 报销单引用员工信息，合同引用客户信息 |
| 数据快照策略 | 主数据修改后，已引用的业务单据如何处理 | 版本快照（不随主数据变化） vs 实时引用（始终取最新） |
| 生命周期 | 启用 / 停用 / 归档 | 客户可停用但不删除，停用后不可新建关联单据 |
| 唯一标识 | 用什么字段保证唯一性 | 客户名称 + 统一社会信用代码 |

### 主数据与业务数据关联规则

- 业务单据创建时：从主数据列表选择，存储主数据 ID + 快照（如需要）
- 主数据停用时：已有引用不受影响，但不可新建引用
- 主数据修改时：根据快照策略决定是否影响已引用单据
- 主数据删除时：如果有引用关系则禁止删除，只能停用

### 需求澄清阶段追问清单

当识别到主数据时，自动补问以下问题：

1. 该主数据的数据来源是什么？（手动录入 / 导入 / 同步）
2. 谁负责维护？（创建 / 修改 / 停用的权限归属）
3. 已有业务单据引用了主数据后，主数据信息变更了怎么办？
4. 是否需要支持导入？如需要，Excel 模板包含哪些字段？

## 数据权限层级

数据权限控制不同角色能看到和操作的数据范围。支持 6 级粒度：

| 权限范围 | 标识 | 含义 | 适用场景 |
|----------|------|------|----------|
| 个人 | `self` | 只看自己创建的 | 经办人看自己的报销单 |
| 部门 | `department` | 看本部门所有数据 | 部门经理看本部门报销单 |
| 部门及下级 | `department_children` | 看本部门及下级部门 | 事业部总监看下属所有部门 |
| 项目 | `project` | 看指定项目的数据 | 项目经理看本项目合同 |
| 区域 | `region` | 看指定区域的数据 | 区域经理看本区域客户 |
| 全部 | `all` | 看所有数据 | 管理员看所有数据 |

### 数据权限建模规则

- 每个角色必须明确其数据权限范围
- 同一角色在不同页面可以有不同数据权限（如员工在报销列表看自己的，在报表看部门的）
- 数据权限与功能权限独立：有"查看"功能权限不代表能看到所有数据
- 管理员角色默认 `all`，但应支持自定义收窄

### 需求澄清阶段追问

1. 每个角色能看到哪些范围的数据？（个人 / 部门 / 全部）
2. 是否存在跨部门查看需求？（如事业部总监看下属部门）
3. 是否存在按项目或区域隔离数据的需求？

## 批量操作

B 端列表页标配能力。当需求涉及列表页时，应主动考虑批量操作。

### 批量操作建模规则

| 维度 | 说明 | 必须明确 |
|------|------|----------|
| 支持的批量操作 | 批量审批、批量导出、批量删除、批量分配、批量转交 | 是 |
| 前置条件 | 选中项是否必须处于同一状态？是否必须属于同一部门？ | 是 |
| 数量限制 | 单次最多操作多少条（默认 100 条） | 是 |
| 部分成功处理 | N 条中 M 条成功，K 条失败 → 如何展示结果 | 是 |
| 权限要求 | 批量操作是否需要更高权限 | 是 |
| 进度展示 | 大批量操作是否需要进度条 | 否 |
| 异步处理 | 超过阈值时是否转为后台异步执行 | 否 |

### 批量操作 PRD 模板

```markdown
### 批量操作说明

| 操作 | 前置条件 | 数量限制 | 部分失败处理 | 权限要求 |
|------|----------|----------|-------------|----------|
| 批量审批 | 选中项均为"待审批"状态 | 单次最多 50 条 | 成功条数 + 失败原因列表 | 审批人角色 |
| 批量导出 | 无 | 单次最多 500 条 | 不适用 | 有导出权限 |
| 批量删除 | 选中项均为"草稿"状态 | 单次最多 100 条 | 成功删除 + 失败原因列表 | 管理员角色 |
```

### 原型挂载点

列表页批量操作区域必须包含：
- 全选 / 反选 checkbox
- 已选中数量展示（"已选择 5 条"）
- 批量操作按钮组
- 操作确认弹窗（危险操作如删除必须二次确认）

## 操作日志与审计

B 端系统标配，也是合规要求。详情页应默认包含操作日志模块。

### 操作日志建模规则

| 维度 | 说明 |
|------|------|
| 记录的操作 | 创建、修改、删除、审批（通过/驳回/撤回）、导出、打印 |
| 记录的变更内容 | 字段名、旧值、新值（仅修改操作） |
| 操作人信息 | 操作人姓名、操作人角色、操作时间、IP 地址 |
| 日志保留周期 | 默认永久保留，可配置归档策略 |
| 日志查询 | 按操作类型、操作人、时间范围筛选 |

### PRD 操作日志 section 模板

```markdown
## 操作日志

### 记录范围
- 创建：记录创建人、创建时间
- 修改：记录修改人、修改时间、变更字段（字段名 + 旧值 + 新值）
- 删除：记录删除人、删除时间（逻辑删除，不物理删除数据）
- 审批：记录审批人、审批时间、审批动作（通过/驳回）、审批意见
- 导出：记录导出人、导出时间、导出条件

### 展示位置
- 详情页底部，独立 Tab "操作记录"
- 默认按时间倒序展示
- 支持按操作类型筛选

### 保留策略
- 在线保留：最近 1 年
- 归档存储：1 年前数据归档到冷存储
- 查询：归档数据仍可查询，但响应时间较长
```

### 原型挂载点

详情页操作日志模块：`data-module-id="module_operation_log"`

## 编码规则

B 端单据几乎都有编号。需求澄清阶段应主动追问编码规则。

### 编码规则建模

| 维度 | 说明 | 默认值 |
|------|------|--------|
| 编号格式 | 前缀 + 分隔符 + 年月 + 流水号 | `{PREFIX}-{YYYYMM}-{0001}` |
| 前缀 | 业务类型标识 | 由业务对象英文缩写决定 |
| 生成时机 | 创建时 / 提交时 | 创建时 |
| 是否可修改 | 创建后是否允许手动修改编号 | 不可修改 |
| 是否连续 | 删除/作废后是否跳号 | 不跳号，流水号只增不减 |
| 跨年重置 | 新年是否重置流水号 | 每年 1 月重置 |
| 并发处理 | 高并发下如何保证编号唯一 | 数据库序列 / Redis 自增 |

### 编码规则 PRD 模板

```markdown
## 编码规则

### 报销单编号
- 格式：EXP-{YYYYMM}-{0004}
- 示例：EXP-202605-0001
- 生成时机：创建报销单时自动生成
- 可修改：否
- 连续性：不跳号，删除后流水号继续递增
- 跨年重置：每年 1 月重置为 0001
```

### 需求澄清阶段追问

1. 单据编号格式是什么？（如有明确要求）
2. 何时生成编号？（创建时 / 提交时）
3. 编号是否允许手动修改？
4. 删除后是否跳号？

## 报表与数据统计

当需求涉及统计、看板、报表、汇总、分析、趋势等关键词时，启用报表建模。

### 报表需求建模模板

| 维度 | 说明 | 示例 |
|------|------|------|
| 统计维度 | 按什么分组统计 | 按部门 / 按费用类型 / 按月 |
| 统计指标 | 计算什么数值 | 总金额 / 笔数 / 平均值 / 同比 / 环比 |
| 筛选条件 | 用户可选的过滤项 | 时间范围 / 部门 / 费用类型 / 状态 |
| 数据口径 | 哪些数据计入统计 | 仅已通过的报销单 / 不含已撤回的 |
| 数据更新频率 | 数据多新 | 实时 / T+1 / 每周一 |
| 图表类型 | 展示形式 | 表格 / 柱状图 / 饼图 / 趋势线 |
| 下钻能力 | 是否支持点击穿透到明细 | 点击部门柱状图 → 展开该部门报销明细 |

### 数据口径一致性规则

- 报表统计数字必须与列表页筛选结果一致
- 数据口径必须在 PRD 中明确写出，不能隐含
- 统计的时间范围、状态过滤条件必须与列表页一致
- 如有差异，必须在 PRD 中说明原因（如报表含历史快照，列表页不含）

### PRD 报表 section 模板

```markdown
## 报表与数据统计

### 报销统计看板

| 统计卡片 | 指标 | 数据口径 | 更新频率 |
|----------|------|----------|----------|
| 本月报销总额 | SUM(amount) | 本月已通过的报销单 | 实时 |
| 待审批笔数 | COUNT(*) | 状态为"待审批"的报销单 | 实时 |
| 平均审批时长 | AVG(审批完成时间 - 提交时间) | 本月已完成审批的报销单 | T+1 |

### 趋势图
- X 轴：月份（近 12 个月）
- Y 轴：报销金额
- 分组：按费用类型
- 下钻：点击某月某类型 → 跳转到对应筛选条件的报销单列表
```

## 导入导出

B 端高频功能。需求中提到"导出""导入""下载""上传"时，应补齐导入导出规则。

### 导出规则建模

| 维度 | 说明 | 默认值 |
|------|------|--------|
| 导出格式 | Excel / CSV / PDF | Excel |
| 导出范围 | 全部 / 当前筛选结果 / 选中行 | 当前筛选结果 |
| 数据量限制 | 单次最多导出多少条 | 10000 条 |
| 导出权限 | 谁可以导出 | 有导出功能权限的角色 |
| 异步导出 | 超过阈值是否后台生成 | 超过 1000 条自动转异步 |
| 异步通知 | 后台生成完成后如何通知 | 站内消息 + 页面顶部提示 |
| 字段范围 | 导出哪些字段 | 列表页可见字段 + 详情页部分字段 |

### 导入规则建模

| 维度 | 说明 | 默认值 |
|------|------|--------|
| 导入模板 | 是否提供模板下载 | 是，首次导入前必须下载模板 |
| 文件格式 | 支持的格式 | .xlsx |
| 文件大小 | 单文件大小限制 | 10MB |
| 字段校验 | 校验规则 | 逐行校验，错误行标红 |
| 错误处理 | 部分成功怎么办 | 成功行导入 + 错误行生成错误报告下载 |
| 重复处理 | 重复数据怎么处理 | 根据唯一键判断：跳过 / 覆盖 / 报错 |

### PRD 导入导出 section 模板

```markdown
## 导入导出

### 导出
- 格式：Excel (.xlsx)
- 范式：当前筛选结果（未筛选时导出全部）
- 数量限制：单次最多 10,000 条
- 异步阈值：超过 1,000 条转后台异步生成
- 异步通知：生成完成后页面顶部出现下载链接，保留 7 天
- 权限：拥有"导出"功能权限的角色

### 导入
- 模板：提供标准 Excel 模板下载
- 格式：.xlsx，单文件 ≤ 10MB
- 校验：逐行校验，错误行标红并显示错误原因
- 结果处理：成功行正常导入，错误行生成错误报告（Excel 格式）供下载
- 重复判断：以"供应商名称 + 统一社会信用代码"为唯一键，重复行跳过并记录
```
