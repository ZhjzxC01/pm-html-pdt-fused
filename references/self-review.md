# 产物自审规范

用途：每个主交付物生成后、提交用户确认前，先执行一轮内部自审，修复明显问题后再交付。

## 通用原则

1. 自审是单个产物内部的一致性检查，与 quality-checks.md 中的产物间交叉检查互补。
2. 自审发现问题时直接修复，不需要额外征求用户同意。
3. 修复后不需要重新自审，直接进入交付确认。

## 功能清单自审

完成功能清单后，逐项检查：

1. **占位符扫描**：是否存在"待定""TBD""TODO""后续补充"等未完成标记。如有，补全或标注"不适用"。
2. **业务对象完整性**：每个业务对象是否有名称、关键字段、状态集合。状态机是否有终态。
3. **角色覆盖**：列出的角色是否覆盖了需求中提到的所有操作主体。
4. **范围边界**：是否明确标注了"本次包含"和"本次不包含"。
5. **待确认问题**：是否有遗留的待确认问题。如有，标注哪些会阻塞原型生成、哪些可以延后。
6. **歧义扫描**：功能描述是否可被两种方式理解。重点关注：操作结果（提交后是草稿还是直接审批？）、数据范围（列表显示全部还是仅自己的？）、默认行为（未配置审批人时如何处理？）。有歧义的功能点标注为 pendingQuestion。

## 原型自审

完成原型后，逐项检查：

1. **页面完整性**：功能清单中提到的每个关键页面是否都有对应原型页面。
2. **导航连通性**：页面间的跳转关系是否完整，是否有死链（无法从任何入口到达的页面）。
3. **状态覆盖**：每个业务对象的状态是否在原型中有对应的界面展示（如列表筛选、详情页状态标签）。
4. **角色差异**：不同角色看到的页面是否有差异体现（如字段可见性、操作按钮）。
5. **异常状态**：是否有空状态、加载状态、错误状态的展示。
6. **实体 ID**：关键元素是否带有稳定的实体 ID 或 data 属性，方便后续标注挂载。
7. **UX 质量（参考 `references/ux-quality-rules.md`）**：
   - 表单标签可见性：每个输入框是否有可见 label
   - 错误反馈位置：错误信息是否在对应字段下方
   - 交互反馈：按钮是否有 hover/active 状态
   - Loading 状态：异步操作是否有加载指示
   - 空状态引导：无数据时是否有引导信息和操作入口
   - 色彩对比度：文字与背景对比度是否达标
   - 设计体系一致性：样式是否与 design-system/MASTER.md 一致
8. **交互完整性**：
   - 每个按钮/链接的点击事件是否有实际响应（不能什么都不做，也不能只弹 alert）
   - 页面内的每个 Tab 面板是否有完整内容（不能只有第一个 Tab 有内容，其余为空白）
   - 每个筛选器/下拉框选择后是否实际过滤了表格数据行
   - 分页控件是否切换了可见数据行（超过 10 行数据时）
   - 删除/驳回等危险操作是否弹出确认对话框
   - 表单提交成功后是否显示 Toast 反馈消息
   - 条件显隐字段在父字段值变化时是否正确显示/隐藏
   - 跨页导航是否可用（如点击列表中的编号是否能跳转到详情页）

## PRD 自审

完成 PRD 后，逐项检查：

1. **占位符扫描**：全文搜索"TBD""TODO""待定""待补充""后续""暂不""略"等标记。每个占位符必须补全或改为明确的"不适用"并说明原因。
2. **章节完整性**：根据需求级别（S/M/L），核对模板要求的章节是否全部存在且有实质内容。
3. **字段引用一致性**：PRD 中提到的字段名、状态名、角色名是否与功能清单和原型中的命名一致。
4. **状态机完整性**：每个状态转换是否有触发动作、执行角色、前置条件。是否存在未定义的转换路径。
5. **权限覆盖**：每个操作是否标注了允许执行的角色。是否有越权场景的处理说明。
6. **异常与边界**：每个关键操作是否有异常处理说明（网络异常、并发冲突、数据不一致等）。
7. **验收条件**：每个功能模块是否有可执行的验收条件。
8. **歧义扫描**：检查是否有规则可被两种方式理解。检查方法：对每个"X 可以 Y"或"X 可以 Y 或 Z"的规则，追问"Y/Z 之后发生什么？"。如果答案不唯一且影响业务流程，标记为 pendingQuestion 而非自行假设。重点关注：审批流转方向（驳回后回到哪？）、状态终态（完成后还能退回吗？）、权限边界（无权限是隐藏还是禁用？）。

## 标注自审

完成标注后，逐项检查：

1. **编号稳定性**：标注编号是否连续、无重复、无跳号。
2. **映射完整性**：每个标注是否能映射到 PRD 的具体章节。
3. **覆盖度**：PRD 中的每个关键规则是否都有对应的标注。
4. **DOM 关联**：每个标注是否关联到原型页面中的具体 DOM 元素。
5. **增量一致性**：如果是增量修改，旧标注编号是否被复用，新增标注是否从已有最大编号递增。

## 自审输出格式

自审不需要生成独立报告。发现问题直接修复后，在交付确认回复中附带一行说明：

```markdown
自审已完成：修复了 2 个占位符、补齐了 1 个缺失的异常状态页面。
```

如果自审未发现问题：

```markdown
自审已完成：无问题。
```
