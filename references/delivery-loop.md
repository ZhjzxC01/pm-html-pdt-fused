# 交付闭环

用途：定义融合版技能的正式交付物、支撑产物和阶段边界。

## 主交付物

正式交付默认只围绕三类：

1. 产品原型：可讨论、可反推 PRD、可挂载标注。
2. `PRD`：覆盖页面、模块、字段、动作、权限、状态机、异常和边界。
3. `PRD` 标注原型：页面标注编号稳定，能反查 PRD、测试用例和权限规则。

## 支撑产物

当前 TypeScript 内核可以继续维护这些支撑产物：

- `project-state.json`：结构化单一事实源。
- `prototype-spec.json`：页面、模块、字段、动作、权限和 mock 数据。
- `prototype-meta.json`：DOM 与实体映射。
- `prototype-annotations.json`：标注与 PRD / 测试 / 权限的映射。
- `test-cases.md` / `gherkin.feature`：验收和测试支撑。
- `flow.mermaid`：状态流转和流程沟通支撑。
- `consistency-report.md`：闭环质量检查报告。

支撑产物用于提高质量，不应替代用户对主交付物的确认。

## 节点完成标准

自动初始化完成：

- 项目目录已创建，包含 `input.md`、`project-state.json`、`raw-materials/` 和 `output/` 目录。
- `input.md` 已写入用户原始需求。
- 目录名从需求自动推断，使用英文短横线命名。
- 如果用户提供了附件，已保存到 `raw-materials/` 目录。

原始资料处理完成（如有原始资料）：

- `raw-materials/` 中的每份文件均已读取并提取关键信息。
- 每条提取信息标注了来源文件名。
- 已整理成结构化摘要，包含角色、流程、规则、字段、阈值等。
- 已识别资料与需求文本之间的矛盾和补充信息。
- 已向用户展示摘要和待确认问题，用户已确认。

对话澄清完成（如有澄清）：

- 所有阻塞功能清单的关键问题已得到回答。
- 用户确认了原始资料提取的信息和澄清结果。
- 不阻塞当前节点的细节已记录为待确认问题，留到后续节点处理。

功能清单完成：

- 有业务对象、角色、核心场景、范围、风险和待确认问题。
- 有状态机初稿。
- 审批流只在出现审批语义时启用。

原型完成：

- 页面能直接打开并讨论。
- 页面包含关键业务对象、状态、主操作、角色差异和异常状态。
- 关键节点带稳定实体 ID 或 data 属性，方便 PRD 反推和标注挂载。

PRD 完成：

- 每个关键页面、模块、字段、动作都有规则说明。
- 状态机、权限、异常、边界和验收条件可执行。
- 能追溯到原型实体和需求来源。
- 无占位符：禁止出现 TBD、TODO、待定、待补充、略等未完成标记。每个 section 必须有实质内容或明确标注"不适用"并说明原因。
- PRD 章节范围由需求级别（S/M/L）决定：
  - **S 级**：轻量需求卡，覆盖基本信息、变更范围、影响分析、当前状态、整体设计、数据处理、通知、非功能需求、上线计划（8 个章节）。
  - **M 级**：功能版 PRD，覆盖 S 级全部章节 + 页面、模块、字段、动作、状态机、权限、异常、边界、验收条件、附录（17 个章节）。
  - **L 级**：完整版 B 端 PRD，覆盖 M 级全部章节 + 数据模型、接口集成、紧急预案、评审记录（21 个章节）。

标注完成：

- 标注以模块为单位聚合，每个功能区域一个标注。
- 浮窗内容完整覆盖该区域全部 PRD 需求点，研发人员无需再读原文档。
- 角标为橙色方块（rgb(250,173,20)），定位在模块右上角，非侵入式。
- 标注编号为数字 1-999，已反写入 PRD section 的 annotationNumber 字段。
- 浮窗支持 Hover 打开、拖拽移动、多窗口同时打开、X 按钮关闭。
- 增量更新时优先复用旧编号。

## 业务确认单

当需求完成 PRD 后，自动生成面向业务方的确认单。业务确认单使用非技术语言，供业务方签字确认。

### 业务确认单内容

| 章节 | 说明 |
|------|------|
| 需求概述 | 用一段业务语言说清楚做什么、为什么做、做完后的效果 |
| 功能清单 | 用业务语言列出本次实现的功能点（不用技术术语） |
| 流程说明 | 简化版业务流程图（业务方能看懂的版本，非状态机图） |
| 影响范围 | 涉及哪些角色、哪些页面、哪些已有功能 |
| 工期预估 | 基于 S/M/L 级别的参考工期 |
| 确认签字 | 产品经理 / 业务方 / 技术负责人 签字区域 |

### 适用场景

- S 级和 M 级需求，给业务方签字确认
- L 级需求通常有正式评审会，业务确认单作为辅助材料

### 业务确认单生成规则

- 从 PRD 提取关键信息，转化为业务语言
- 去除所有技术术语（字段标识、校验规则、状态机枚举等）
- 流程图使用简单的方框箭头，不使用 BPMN 或状态机语法
- 保留关键业务规则（如"超过 10 万需要总经理审批"）
- 输出格式：Markdown 文件，文件名 `<project>-业务确认单.md`

## 上线交付包

一致性检查通过后，自动生成上线交付包，包含配置清单、检查清单和培训大纲。

### 上线交付包内容

**1. 权限配置清单**

从 `project-state.json` 的 permission 实体反推：

| 角色 | 菜单权限 | 按钮权限 | 数据权限 |
|------|----------|----------|----------|
| 经办人 | 报销单列表、新建报销单 | 提交、撤回、导出 | self |
| 主管 | 报销单列表、审批列表 | 审批通过、驳回、转交 | department |
| 财务 | 报销单列表、财务复核 | 复核通过、驳回、导出 | all |

**2. 字典配置清单**

从 field 的枚举值反推：

| 字典编码 | 字典名称 | 新增选项 | 操作 |
|----------|----------|----------|------|
| expense_type | 费用类型 | 差旅、办公、招待、交通、其他 | 新增字典 |
| approval_status | 审批状态 | 草稿、待审批、已通过、已驳回、已撤回 | 新增字典 |

**3. 上线检查 Checklist**

- [ ] 功能验收：核心流程走通
- [ ] 权限配置：所有角色权限已配置并验证
- [ ] 字典配置：所有枚举值已配置
- [ ] 数据迁移：历史数据已迁移并验证（如有）
- [ ] 接口对接：外部系统接口联调通过（如有）
- [ ] 灰度方案：灰度发布范围和回滚条件已确认
- [ ] 回滚方案：回滚步骤已文档化
- [ ] 监控告警：关键指标监控已配置
- [ ] 培训通知：相关角色已收到培训通知

**4. 培训材料大纲**

| 培训对象 | 重点内容 | 培训方式 |
|----------|----------|----------|
| 普通员工 | 如何提交报销单、查看进度 | 操作手册 + 短视频 |
| 审批人 | 如何审批、驳回、转交 | 操作手册 + 模拟演练 |
| 管理员 | 如何配置权限、导出数据、查看报表 | 一对一面谈 |

### 输出文件

- `<project>/output/上线交付包.md`：包含上述全部 4 部分
- `<project>/output/权限配置清单.xlsx`：角色-权限矩阵表（可选，供运维直接配置参考）
- `<project>/output/培训大纲.md`：按角色组织的培训内容大纲

## 需求摘要（一页纸）

面向管理层的精简需求摘要，适用于给领导汇报、立项评审。

### 内容结构

| 章节 | 字数限制 | 说明 |
|------|----------|------|
| 背景和目标 | 50-100 字 | 为什么做，做完后达到什么效果 |
| 方案概述 | 100-200 字 | 怎么做，3-5 句话讲清楚核心方案 |
| 影响范围 | 50-100 字 | 涉及哪些模块、多少页面、影响多少用户 |
| 工期预估 | 50 字 | 基于 S/M/L 复杂度的参考工期 |
| 风险和依赖 | 50-100 字 | 主要风险点和外部依赖 |

总字数控制在 300-500 字以内。

### 生成规则

- 从 PRD 中提取关键信息，精简为一页纸
- 使用业务语言，避免技术术语
- 重点突出"为什么做"和"做完后效果"
- 工期预估参考：S 级 1-3 天、M 级 1-2 周、L 级 2-4 周（仅参考，以技术评审为准）
- 输出文件：`<project>/output/需求摘要.md`

## 操作手册生成

基于原型和 PRD 自动生成面向终端用户的操作手册大纲。

### 组织方式

支持两种组织方式，可同时生成：

**按角色组织：**

| 操作手册 | 目标读者 | 内容范围 |
|----------|----------|----------|
| 员工操作手册 | 普通员工 | 新建单据、提交、查看进度、撤回 |
| 审批人操作手册 | 主管/经理 | 待办列表、审批、驳回、转交、批量审批 |
| 管理员操作手册 | 系统管理员 | 权限配置、数据导出、报表查看、系统设置 |

**按场景组织：**

每个操作包含：入口路径 → 操作步骤 → 注意事项 → 常见问题

示例：
```markdown
## 如何提交报销单

**入口路径：** 首页 → 报销单列表 → 新建报销单

**操作步骤：**
1. 点击"新建报销单"按钮
2. 选择费用类型（差旅/办公/招待/交通/其他）
3. 填写报销金额（必须大于 0，最多 2 位小数）
4. 上传发票附件（jpg/png/pdf，单文件 ≤ 10MB）
5. 填写报销事由（可选）
6. 点击"提交审批"

**注意事项：**
- 提交后无法修改，如需修改请先撤回
- 金额超过 5000 元需财务复核
- 发票不可重复报销

**常见问题：**
Q: 提交后发现金额填错了怎么办？
A: 在审批人处理前，可以点击"撤回"按钮撤回单据，修改后重新提交。
```

### 输出文件

- `<project>/output/操作手册-按角色.md`：按角色分章节的操作手册
- `<project>/output/操作手册-按场景.md`：按使用场景分章节的操作手册
